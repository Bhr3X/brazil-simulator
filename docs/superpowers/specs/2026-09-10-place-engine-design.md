# Place Engine — Broad Design Spec

Date: 2026-09-10
Status: SUPERSEDED on 2026-09-10 by `2026-09-10-one-local-day-platform-design.md` (runtime generation, transplant strategy, no-asset visuals). Kept for the browser-only analysis and the module-by-module inventory.
Repo: `/Users/bhreno/First Person Engine` (Brazil Simulator // Sobrevivência BR)

## 1. Purpose

Turn the single hand-built Pirituba map into an engine that, given a location, generates a
walkable world (streets, stores, NPCs, radio, dangers) from public data plus an LLM, and keeps a
player supplied with content for a 10 to 15 minute walk. Do it without starting from scratch.

## 2. Decisions already made

| Decision | Value |
|---|---|
| Engine | Stay on Three.js. Unreal rejected (no web export, kills distribution). |
| Strategy | Strangler refactor. Extract, don't rewrite. Only `CityBuilder.js` and `main.js` are rewritten. |
| Platforms | Browser only. Desktop browser and mobile browser, both "pristine". No Electron, Tauri, or store builds. |
| Orientation | Portrait is a full play mode, full-bleed. Landscape and desktop stay as today. |
| Input | Keyboard and mouse, touch, gamepad. |
| Gameplay | Being redesigned to be text-free. Dialog menus are legacy. Feedback is sound, meters, hands, icons, voice. |
| Determinism | Economy and events stay seeded (I2). LLM output is build-time data, never runtime logic. |
| LLM cost | Zero per player session. |
| Session | 15-minute run, 06:00 to 06:00, stays. A director fills it. |
| Threats | Physical. Hands already punch. NPCs will approach, threaten, rob, flee. No separate combat system. |
| Scope of "location" | São Paulo neighborhoods from a curated list first. Brazil later. |

Assumed, not yet confirmed by the user: items in the table marked as defaults in the 2026-09-10 jam
(SP first, build-time packs, OSM graph, engine serves Brazil Simulator only, phase 0 = Pirituba as data).

## 3. Non-goals

- Runtime LLM calls in the browser in phases 0 to 2.
- Copying Street View imagery into textures (violates Google Maps terms). Panos are LLM reference only.
- A general-purpose engine package for other studio games. Revisit after phase 2.
- Real 3D art assets. The world stays procedural kit geometry with generated textures.

## 4. Target architecture

Six layers. Data flows down. No layer imports from a layer above it (extends I13).

```
tools/place-author   (offline, Node)   raw public data + LLM  ->  packs/<place>.json
        |
src/world            PlaceSpec schema, compiler, kits, tiles, zones (generated)
src/sim              rng, clock, state, events, director, npc behaviors, items, quests
src/engine           renderer (+GLSL ASCII pass), physics, controls, traffic, streaming
src/platform         capabilities, input, layout, storage
src/audio            unchanged, plus per-pack asset manifest
src/ui               hud, feedback table, menus (thin)
src/main             bootstrap only
```

Dependency rule: `platform <- engine <- world <- sim <- ui <- main`. `audio` may be used by `sim` and
`ui`. Nothing imports `main`.

## 5. Data contracts

### 5.1 PlaceSpec (one file per place, versioned, validated)

```
PlaceSpec {
  id, version, name, locale, center: {lat, lng}, bounds
  culture: { classWeights: {DE, C, AB}, genres: [...], slang: [...], dangerCurve: [24 numbers] }
  streets: { nodes: [{id, x, z}], edges: [{a, b, kind, lanes, width}] }
  lots:    [{ id, footprint: [[x,z]...], kind, floors, kit, style, hours? }]
  pois:    [{ id, lotId?, kind, name, hours: {open, close}, station: {...}, genre?, emitter? }]
  npcs:    [{ id, archetype, name, home: poiId|nodeId, schedule: [{from, to, at}], loadout }]
  items:   [{ id, soldAt: poiId, priceCentavos, effects }]
  beats:   [{ id, kind, when: {hours, zone?, perigoMin?}, weight, cooldown, payload }]
  quests:  [{ id, template, params }]
  radio:   { stations: [...], newsSeeds: [...] }
  assets:  { audio: [...], textures?: [...] }
}
```

Kinds and archetypes are closed enums owned by the kits and the sim. The LLM may only choose from
them. Anything outside the enum fails validation at build time.

### 5.2 Tile (compiler output, runtime unit)

```
Tile { tx, tz, seed, meshes: InstancedMesh refs, colliders: AABB[], zones: Zone[],
       anchors: Anchor[], spawns: Spawn[], emitters: Emitter[], lanes: Lane[] }
```

Tile size 32 m. Seed = hash(placeId, runSeed, tx, tz). Everything in a tile is disposable.

### 5.3 Kit prefab contract

```
Prefab { id, footprint: {w, d}, height, build(ctx, rng, style) -> { geometry group, colliders,
         anchors, emitters }, variants }
```

Prefabs are the only geometry authors. The compiler places prefabs on lots and street furniture on
edges. Ten to fifteen prefabs reproduce Pirituba: sobrado, boteco, padaria, adega, posto, banca,
barraca, laje, escadão, poste, ponto de ônibus, orelhão, árvore, torre, casa.

### 5.4 Event (the text-free feedback contract)

```
Event { id, deltas, at: {x, z}, source }
FeedbackRow { eventId, sound, meterPulse, handAnim, icon, voice? }
```

`GameState.apply(deltas, eventId)` emits the event. `ui/feedback` looks up the row. No system
renders text for gameplay outcomes.

### 5.5 Beat (director output)

```
Beat { id, kind: 'npc_approach'|'threat'|'spawn_item'|'quest_step'|'radio'|'weather'|'traffic',
       target: anchor|npc|tile, expiresAt }
```

## 6. Systems

### 6.1 Platform

Capabilities object built once: touch, pointerLock, fullscreen, gamepad, safeArea insets,
orientationLock, tts, storage. No `navigator` sniffing outside this module. Input module maps
keyboard, mouse, touch, and gamepad to intents: move, look, sprint, crouch, jump, useLeft,
useRight, dropLeft, dropRight, interact, menu.

### 6.2 Layout

Chosen by aspect ratio, never by device. Portrait: full-bleed viewport, stick bottom-left, two hand
buttons bottom-right, meters as icons along the top under the safe area. Horizontal FOV is held
between 55 and 75 degrees and converted to Three.js vertical FOV from aspect. Rotation mid-run
re-anchors everything without state loss.

### 6.3 Renderer

Add `AsciiPass`: render scene to a `WebGLRenderTarget` with a `DepthTexture`, then one fullscreen
fragment shader samples luminance and depth, picks a glyph from a glyph atlas texture, and applies
mode (color, matrix, amber, cyber, braille, thermal, dither, comic, vhs). Density and depth
scaling become uniforms. CPU path stays as fallback when WebGL2 is unavailable. RETRO_3D and
wireframe bypass the pass as today.

### 6.4 World compiler

`compile(PlaceSpec, runSeed) -> TileIndex`. Pure function, no Three.js in the placement step so it
is unit-testable. Placement: lots to prefabs by kind and footprint, edges to road planes, lanes,
poles, signs, crossings. Zones, anchors, emitters, spawns are emitted per tile. Instancing:
`BatchedMesh` or `InstancedMesh` per prefab variant, texture atlas per kit.

### 6.5 Streaming

Player-centred ring. Load tiles within 2, dispose beyond 3. Physics colliders and audio emitters
register and unregister with their tile. NPCs whose home tile unloads freeze and are restored from
their schedule when it reloads. Traffic lanes are per tile and stitched at edges.

### 6.6 Director

Runs every sim minute. Inputs: clock, player state, zone, tiles loaded, time since last beat, beats
already fired. Holds a budget: at least one beat every N sim minutes (N tuned per class), never two
threats within M minutes, danger curve from the PlaceSpec scales threat weight by hour. Picks from
the beat table by weight and cooldown using the seeded `Rng`. Emits Beats. The two scripted events
today (moto, blitz) become beats with `when` gates and cooldown zero.

Quest templates: fetch (item from poi A to poi B), reach (poi by hour), avoid (keep perigo under X
until hour), earn (grana delta by hour). Class objective becomes the run's root quest.

### 6.7 NPC behaviors

State machine per NPC: idle, roam, approach, threaten, rob, flee, arrest, trade. Routes are A* on
the PlaceSpec street graph, so no navmesh. Perception is distance plus a cheap facing check.
Threat NPCs are spawned by director beats near the player, not placed at start.

### 6.8 Items and hands

`ITEM_TYPES` moves to the pack's items table plus a small engine catalogue for effects. `use()`
returns an event id. All rolls use `Rng`. Robbery and confiscation are beats.

### 6.9 Audio

Unchanged engine. Pack manifest lists MP3s and vinhetas. Zone to genre map comes from
`pois[].genre`. News desk reads pack `newsSeeds` and recorded actions through TTS.

### 6.10 Place author (offline tool)

Node CLI in `tools/place-author/`.

1. Geocode the place name (Nominatim).
2. Fetch OSM via Overpass: highways, building footprints, `shop=*`, `amenity=*`, `leisure=*`.
3. Fetch facts: Wikipedia summary, IBGE income distribution for the district if available.
4. LLM step: Claude `claude-opus-5` through the Messages API with structured outputs
   (`output_config.format`) producing the `culture`, `pois[].name/station`, `npcs`, `items`,
   `beats`, `radio` fields, constrained to the closed enums. Bulk runs go through the Batches API
   at half price. Output is cached by hash(lat, lng, schemaVersion, promptVersion).
5. Validate against the PlaceSpec JSON Schema. Emit `packs/<id>.json` plus an asset manifest.

The LLM never touches geometry coordinates. It names, describes, weights, and schedules.

## 7. Stack recommendation

| Concern | Recommendation | Why, and what it replaces |
|---|---|---|
| Language | TypeScript for new modules, `allowJs` for existing files, JSDoc types added opportunistically | Contracts (PlaceSpec, Event, Beat) need types for agents to refactor safely. No forced rewrite. |
| Bundler | Vite with esbuild, `vite-plugin-singlefile` for the standalone build, `vite-plugin-pwa` for the manifest and cache | Replaces the regex concat in `build.js`, which is fragile. Keeps I1 (standalone generated, never edited). Adds code splitting so packs load lazily. |
| Rendering | Three.js from npm at a current release, `BatchedMesh`, `WebGLRenderTarget`, `DepthTexture` | Pinned minified file cannot be upgraded or tree-shaken. WebGL2 is the mobile baseline. WebGPU not yet. |
| Physics | Keep the custom AABB engine | 274 lines, works, the game is boxes and a ball. Rapier only if physical combat ever needs it. |
| Audio | Keep Web Audio synth plus MP3, add manifest | No change needed. |
| Schema | JSON Schema for PlaceSpec, validated with Ajv in the tool and in tests | Packs are data; bad data must fail at build, not at runtime. |
| Pathfinding | A* on the street graph, in `sim/npc` | OSM gives the graph. No navmesh library. |
| State | Keep `GameState.apply` as the single mutation path, add typed event ids | Already exists. |
| Persistence | `localStorage` for settings, Cache Storage via the service worker for packs and audio | Runs are 15 minutes; no save system needed yet. |
| Tests | Playwright (Chromium) replacing the raw CDP script, same assertions, plus a viewport matrix and mobile emulation. Vitest for pure modules (compiler, director, rng). | Playwright is CDP with a maintained API and device profiles. Pure modules get unit tests for the first time. |
| LLM | Anthropic TypeScript SDK in `tools/`, `claude-opus-5`, structured outputs, Batches for bulk | Build-time only. No key in the client. |
| Data sources | Overpass API, Nominatim, Wikipedia REST, IBGE SIDRA | All free, all public, all cacheable. |
| Hosting | GitHub Pages and itch.io as today, packs as static files | No server. A Cloudflare Worker proxy only if runtime LLM is ever added. |

## 8. Migration path

Each phase ships to itch.io. Each phase has an exit test.

| Phase | Deliverable | Exit test |
|---|---|---|
| 0 | Vite build, Playwright port of the CDP suite, `packs/pirituba.json`, compiler and 10 to 15 prefabs reproduce today's map | Suite green. Mesh, collider, zone, anchor counts match a golden file. Standalone parity kept. No visible change. |
| 0.5 | Platform layer, input intents with gamepad, aspect-driven layout, portrait full-bleed, PWA manifest, safe areas, viewport matrix in tests | Suite green at desktop, phone portrait, phone landscape. Rotation mid-run keeps state. |
| 1a | `BatchedMesh` kits, `AsciiPass` GLSL with CPU fallback | 60 fps on a Moto G class phone in both orientations. Draw calls under 50. |
| 1b | Tiles, streaming, seeded per tile, director with beat table, NPC state machine, feedback table, Encounters retired | Walk 15 minutes in a 3x Pirituba with a beat at least every N sim minutes. Same seed gives the same beat log. |
| 2 | `tools/place-author`, second SP neighborhood pack, place picker | Second pack validates, compiles, and passes the same suite with no code change. |
| 3 | Curated SP list, per-place radio and news, polish | Any listed place loads under 3 s on 4G. |

Phase 0 is the go or no-go probe for the whole plan. If the compiler needs a special case per
building, the kit abstraction is wrong and we learn it before anything else is built.

## 9. Testing strategy

- Unit (Vitest): compiler placement, director selection under a fixed seed, rng streams, layout math,
  PlaceSpec validation with good and bad fixtures.
- Golden: `packs/pirituba.json` compiles to known counts per tile.
- Determinism: seed 42 produces an identical beat log and end state across two runs.
- Browser (Playwright): existing behaviors ported, zero console errors, three viewports, touch and
  gamepad intents injected, rotation mid-run.
- Perf: frame time sampled in Playwright with CPU throttling as a proxy for phones. Real device
  check on one Android and one iPhone per phase.

## 10. Invariants

Changed:
- I1: the standalone bundle is produced by the bundler, never edited by hand.
- I12: zones are generated from PlaceSpec by the compiler, never hand-written.
- I13: dependency rule extended to the six layers in section 4.

Added:
- I14: PlaceSpec is the only source of spatial data. No literal world coordinates in `src/`.
- I15: layout, input, and capabilities derive from `platform/`. No `navigator` or `window.inner*`
  sniffing elsewhere.
- I16: LLM output is build-time data validated against the schema. No runtime LLM call in the game.
- I17: every gameplay outcome is an event id with a feedback row. No gameplay text rendering.

## 12. Risks and open questions

| Risk | Mitigation |
|---|---|
| Kit abstraction fails on Pirituba | Phase 0 exit test, cheap to learn |
| OSM coverage is thin in some SP districts | Author falls back to seeded procedural lots on the real street graph |
| Portrait FOV feels wrong | Tune the 55 to 75 range on device in phase 0.5, ASCII hides stretch |
| Tests depend on dialog text today (88 refs) | Port to state and event assertions in phase 0, before dialogs are retired |
| `Math.random` in new code (HandsSystem) | Lint rule banning `Math.random` outside `Rng.js` and cosmetic audio |
| Three.js upgrade changes rendering | Pin a version in phase 0, golden screenshot in RETRO_3D |

Open questions for the user:

4. Is the current uncommitted work (hands, doors, quick actions) the shape of the text-free design, or an intermediate step?
