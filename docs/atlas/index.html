Architecture atlas / proposed design / 10 September 2026

One place. One unpredictable day.

A 15-minute browser life-sim: pick a real location, become someone local, improvise under pressure, and hear the neighborhood react.

Two clocks, one coordinated experience

Setup is variable and outside the run. World entry starts 15 active minutes = 24 game hours. Hidden-tab and explicit pause time do not consume the day.

Before 0:00 / startup targets, not measurements
BEFORE TRIGGER

Explore the globe

Pan, rotate and zoom, or search an address. Show land and street-level coverage eligibility. Preview the precise spawn before confirming.

TRIGGER · CONFIRM PLACE

Fork the work

Assign seed + run ID. Start context, geography, appearance, story and music jobs in parallel. Return the character screen immediately from cached assets.

SETUP · USER-PACED

Become someone local

Regional wardrobe target: 1–3 s warm / 3–10 s cold. Choose a seeded role; customize the body and outfit. Late options never reset an existing choice.

READY GATE → 0:00

Enter a playable block

World-ready target: 8–15 s warm / 20–45 s cold from confirm. Wait for character confirmation, safe geometry and a validated opening—not every generated asset.

Warm = regional/geometry assets already cached; cold = eligible location without a prepared pack. These are proposed service targets. First-ever worldwide locations can miss them and must expose progress or a valid fallback.

World entry is an AND gate: character confirmed + playable opening ready. Target readiness is 8–15 seconds warm or 20–45 seconds cold; the player may spend longer customizing. Neither 15s nor 45s automatically starts the run. Music and later content can cross into the active day.

Engine systems and their contracts

This is a proposed architecture, independent of the prototype’s stack. Browser systems execute the solo simulation; backend workers research, generate and validate content.

D

Place picker

Browser + API · Search as requested; validate on confirm
Reads
Pan / rotate / zoom, address query
Produces
Confirmed coordinate, country/city, coverage receipt

Land mask + nearest street-level coverage + reachable spawn. Ambiguous addresses require selection. Coverage is not proof of rights.

D

Run coordinator

Backend · Immediately on confirm; provider events
Reads
Location, seed request, client capabilities
Produces
Job graph, run ID, deadlines, progress

Idempotent jobs keyed by run/version; priority P0 opening, P1 reserve, P2 polish. Cancel old selection epochs; late results never overwrite a newer choice.

M

Geography resolver

Backend · At confirm, then frontier demand
Reads
Licensed roads, footprints, elevation, POIs
Produces
GeoPack with provenance and quality flags

Preserve street topology and landmark placement where data supports it. Missing height uses a labelled estimate. No imagery scraping or assumed reconstruction rights.

AI

Context researcher

Backend · One bounded parallel research batch; reuse regional cache
Reads
Country → city → neighborhood → address
Produces
Source-backed PlaceContext

Separate dated facts from fictional material. Country GDP is broad context, not an individual wealth or danger score. Missing local data stays unknown.

M

Wardrobe author

Backend + browser · P0 cached options; fresh refinements before selection locks
Reads
Climate, visual culture, approved asset catalog
Produces
AppearanceCatalog + compatible variants

Head / torso / legs / feet, apparel, hair, facial hair, body/sex presentation. Assemble known rigged parts first; avoid generating bespoke 3D meshes on the critical path.

AI

Identity & quest author

Backend · During setup; finish before ready gate
Reads
PlaceContext, rules, role templates
Produces
CharacterSpec + urgent GoalGraph

Generate a profession, means, starting items and absurd task. Recommended default: accept a seeded identity or choose among three valid alternatives. Appearance is cosmetic unless an item declares an affordance.

AI

Encounter & item author

Backend · Setup and reserve refill
Reads
Context, businesses, action vocabulary, director demand
Produces
EncounterPack, ItemSpec, dialogue, jokes

Fill authored templates with new local details. Models may propose names, lines, costs within bounds and supported effects; never executable code or new engine powers.

D

World-law compiler

Backend + worker · Every publication
Reads
Candidate packs, rule version, geography
Produces
Validated manifest, chunks, nav and collision data

Check schemas, IDs, currencies, reachable routes, open hours, costs/rewards, quest solvability, asset compatibility and content provenance. Reject or repair once; then use a valid fallback.

D

Chunk streamer

Browser worker · Continuous demand, bounded frame uploads
Reads
Position, velocity, reachable road graph, memory budget
Produces
Resident mesh/collider/nav/audio sets

Near collision safety ring; medium navigation ring; farther visual ring. Pin quest anchors and vehicle exit areas. Persist mutations before unload.

D

Renderer & cameras

Browser · Per frame; target 60 desktop / 30 mobile
Reads
World state, meshes, animation, device budget
Produces
First / third person view

Same simulation for both views. Camera collision prevents wall clipping; first-person hands and third-person body share one rig/state. Dynamic detail and resolution preserve controls.

D

Input & vehicles

Browser · Fixed simulation ticks
Reads
Keyboard, touch, pointer, camera, seat state
Produces
Timestamped gameplay intents

Walk / sprint / use / carry / enter / exit / steer / brake. Validate seat ownership, safe exit, collision and speed. Mobile uses dedicated driving controls after entering a vehicle.

D

State & world rules

Browser authoritative for solo run · Fixed tick, independent of rendering
Reads
Player/NPC intents, clock, validated effects
Produces
Atomic deltas + event IDs

Own hunger, sanity, danger, skill, currency minor units, debt, inventory, damage and defeat. Backend authors never mutate live meters. Multiplayer/competitive authority is outside this design.

D

NPC & traffic simulation

Browser / worker · Near actors tick; far actors summarized
Reads
Schedules, perception, witnesses, roads
Produces
Roam, trade, approach, threaten, flee, chase

NPCs have state, memory, ownership and line-of-sight. Danger has spatial causes and witnesses. Scripted traffic lanes and drivable vehicles share road rules.

D

Pacing director

Browser · Proposed 1 active-second cadence
Reads
State, zone, distance/time since action, reserve, objectives
Produces
Scored encounter request / selected beat

Eligibility → reachability → score → seeded tie-break → schedule. Execution returns through the state gate. AI supplies the pool; the director does not invent rules.

D

Event journal

Browser + persistence API · On each meaningful transaction
Reads
Committed state transaction
Produces
Event ID, tick, actors, location, deltas, facts

Feeds quests, achievements/ending, NPC memory, director, radio and telemetry. Deduplicate IDs and record chunk activation ticks. Keep the journal independent of prose.

M

Radio newsroom

Backend + browser · Event-driven; candidate bulletin every 60–120 s
Reads
Journal fact bundle, language, station personality
Produces
Checked script → TTS → segment queue

Do not narrate uncommitted intent as fact. Discard expired news. Template fallback if generation is late. Radio reports scheduled weather; never owns the weather clock.

M

Music & sound

Backend media + browser audio · Start jobs at confirm; mix locally throughout
Reads
Regional palette, world/zone, action events
Produces
Fresh tracks, vignettes, cached SFX, spatial mix

Cache reusable beds; generate original music in local genres. Prioritize interactive SFX latency. Duck music for news; audio begins on user gesture. Captions/mute remain available.

M

Archive & telemetry

Backend + client storage · Pack publish, checkpoints, run end
Reads
Packs, versions, event IDs, runtime timings
Produces
Scenario ID, replay log, quality/cost evidence

Store generated outputs once. Measure time to input/action, gaps between events, completion, errors and provider spend. Save on visibility loss; gameplay clock pauses while hidden.

The shared data boundary

PlaceContext

Coordinates, region IDs, locale/currency, climate, source URL/date/confidence; culture and economic facts separated from invented jokes.

Researchers → appearance, story, geography and music authors

AppearanceCatalog / CharacterSpec

Rig-compatible head/torso/legs/feet + accessories, hair/facial hair/body presentation; role, starting resources, declared item affordances and goal ID.

Wardrobe and identity authors → compiler → character screen / simulation

GeoPack / WorldChunk

Road graph, footprints, elevation, POI anchors, collision/nav data, region/time zone, provider/license/version, chunk hash. Persistent deltas live outside disposable geometry.

Geography + compiler → streaming, physics, traffic, NPC navigation

EncounterSpec / GoalGraph

Preconditions, actor/anchor IDs, supported action IDs, bounded effects, outcomes, cooldown, expiry, dependencies, fallback, travel-time budget.

Authors → compiler → director → simulation

RunManifest

scenarioId, location, seed, content hashes, rules/PRNG versions, character options, fallback versions, admission log and timestamps.

Coordinator + archive → client start gate / future shared runs

GameEvent / RadioSegment

Event ID, sim tick, actor/object/location IDs, committed deltas, factual summary. Radio segments reference source event IDs and expiry.

State gate → journal → quests, NPC memory, director, newsroom

JobEnvelope

runId, selectionEpoch, jobKey, input hashes, priority, deadline, cost cap, attempt count, output version and state.

Coordinator ↔ durable queue ↔ provider adapters; failed or stale results never activate

World laws are versioned code and configuration: currency precision, transactions, gravity/collision, ownership, item capabilities, NPC perception, visibility, navigation, opening hours, damage, recovery, cooldowns and terminal conditions. Generated content can select supported rules and tune bounded values; it cannot bypass them.

Authored situations, room to improvise

Build a reusable action vocabulary and let generated encounters combine it. A model can write a new delivery job; the engine already knows carrying, payment, theft, vehicle use and deadlines.

One job, several routes

A fictional café needs an urgent delivery. The player may walk, use a bicycle, pay someone to help, or barter for a repair. Taking an owned vehicle can trigger a witness and pursuit.

The same item, ownership, path, transaction and NPC rules resolve all routes. Unsupported free-text wishes are not silently turned into new abilities.

A director with limits

Every active second: filter by clock, zone, prerequisites, visibility and cooldown; check travel time; score urgency, novelty and player needs; break ties with a named RNG stream.

Targets to tune: useful opening action in 20–30 s; usually 30–60 s between meaningful opportunities; three minutes of reserve; one major threat at a time and 90 s major-threat cooldown. These are initial hypotheses.

Real place, fictional drama

Keep real road alignments, slopes and recognizable landmarks where source data allows. Interior layouts and everyday characters can be fictional. Local business metadata helps anchor commerce; jokes and criminal plots use fictional entities.

Regional facts supply flavor and economic scale. They do not directly assign intelligence, crime or personality to individual residents.

World size follows mobility

Prefetch distance ≥ speed × (P95 fetch + compile + upload latency + safety margin). At a design cap of 15 m/s and 10 s total horizon, keep at least 150 m ready ahead, plus braking room and branch coverage.

That speed can cover 13.5 km in 15 minutes. Use a road corridor and predictable speed limits, not a huge fully detailed disk. At an unready boundary, pause consistently with a visible loading transition; never drive into missing collision.

Use independent streams for geography, loot, NPCs, encounters and cosmetics. Changing a hairstyle must not consume the random draw that decides a robbery. Admit async results only at safe ticks and pin the selected version. Gameplay cannot depend on provider completion order.

Proposed character default: generate one funny local identity, with two optional alternatives available during setup. Keep class/profession and starting pressure explicit. Cosmetic body/sex presentation does not determine difficulty. Gear has only the capabilities declared by its item definition.

Failure and recovery paths

Slow research or model failure

Use the validated regional pack and deterministic encounter templates. Bound retries and spend; keep valid gameplay running.

Never block an interaction while waiting for an LLM.

No usable geographic data

Coverage is a gate before confirmation. If a selected address cannot supply safe geometry, show the limitation and nearby eligible alternatives.

Do not secretly move the player or label invented geometry as an accurate reconstruction.

Invalid or late generated content

Reject malformed IDs, unsupported actions, impossible routes and stale run versions. Repair once where the deadline allows; otherwise keep fallback content.

Already visited geometry, rewards and NPC commitments remain stable.

Audio late, silent or unavailable

Play cached beds, SFX and vignettes. Use approved text captions and templates for essential information.

Audio initialization follows a user gesture; permission/network failure does not stop the run.

Player ignores the objective

Offer useful opportunities near plausible routes; let the objective fail honestly. The director cannot teleport a known destination or rewrite a completed action.

If no action occurs, distinguish exploration from a stalled/unreadable opening.

Pause, disconnect or quit

Use a shared pause owner for gameplay clocks and input. Persist the attempt; backend jobs may finish but activation waits until resume.

Early defeat or 15:00 commits one ending, then cancels unnecessary generation.

Minimal waiting needs prepared building blocks

The recommended approach combines reusable regional assets with fresh per-run story and music. Generating every mesh, voice and track from scratch before entry conflicts with minimal waiting.

The exact entry gate

Character confirmed; one safe spawn; usable collision/navigation; reachable income and recovery; a valid goal with at least one feasible solution; opening encounters and essential UI/assets. Core fallback templates can sustain a complete day.

GPU uploads are ready and controls respond. Optional clothes, far-away blocks, rich research, new songs and later stories continue in parallel.

Worldwide is the coverage goal

Start with an explicit eligibility layer: land, nearby street-level coverage and sufficient licensed geographic data. Preserve the selected coordinate and record data quality.

High-fidelity reconstruction from Street View is gated by rights and data access. A playable alternative uses open/licensed roads, buildings and elevation plus regional art kits. It is approximate where source geometry is incomplete.

Material dependency: Google Maps’ standard terms restrict deriving new content from Maps content, including caching/extraction restrictions. A street-level image is not a ready collision mesh. Keep a permitted map/coverage surface separate from the source pipeline for generated gameplay. Source: Google Maps terms §3.2.3.

Evidence needed before promising the experience

Opening journey

Measure confirm → usable wardrobe, ready gate, world entry and first meaningful action. Report median and P95 separately for warm/cold places.

Slow phone networks, low-end devices and first-ever places must be included.

Fifteen-minute content supply

Play walking and driving routes; log time/distance between opportunities, reserve underruns, repeated beats, unreachable goals and late quest offers.

A passing schema is not evidence of an interesting day.

Actual browser play

Observe desktop, portrait and landscape; first/third person; vehicle entry/exit; camera walls; pause/resume; audio denied; touch cancellation.

Frame-time targets: 16.7 ms desktop and 33.3 ms mobile. These are targets, not observed performance.

Rules and replay

Check shared scenario consistency, seed stream independence, atomic transactions, stable chunk reloads and radio source-event accuracy.

Use the same logical input trace; keep physical replay limitations explicit.

Gaps that matter to this architecture

The hands system uses Math.random() for a cash effect, despite the RNG invariant. Seed existence alone does not prove deterministic runs.

Worldwide source ingestion, validated runtime authorship, a general pacing director, rich NPC reactions and driveable-world streaming are proposed capabilities. No browser playtest or quality assessment was performed for this map.

External sources

Google Maps terms §3.2.3 ↗

Standard terms restrict extracting/caching Maps content and creating content based on it. A Street View-derived playable reconstruction needs an appropriate permission path; the map does not assume one.

Street View metadata ↗

Metadata provides availability information. Check coverage near the intended spawn; a returned panorama is not a terrain model or guarantee of whole-route coverage.

Maps pricing ↗

Geographic-service charges vary by API, volume and free usage. The calculator uses an explicit allowance, not a quoted all-in map price.

OpenStreetMap license ↗

Roads and footprints can come from open data under ODbL and its attribution obligations. Dataset coverage and building detail vary; inspect the selected area.

Gemini API pricing ↗

Illustrative paid standard Gemini 2.5 Flash: $0.30 / million input tokens, $2.50 / million output including thinking; Search grounding $35 / 1,000 prompts after free quota.

ElevenLabs API pricing ↗
